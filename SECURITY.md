# Security and privacy policy

## Reporting a vulnerability

Use GitHub private vulnerability reporting when available. Do not open a public issue containing credentials, private notes, exploit details, or personal information.

Include the affected file or workflow, impact, reproduction steps, and a suggested mitigation if known.

## Supported versions

Security and privacy fixes target the latest version on the default branch.

## Important boundary

This framework cannot guarantee that an AI provider, sync service, plugin, or Git host protects data you send to it. Review each service's settings and data policy. Keep secrets outside the vault, use a private repository for personal content, and review staged changes before every push.
